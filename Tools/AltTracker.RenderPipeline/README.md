# AltTracker.RenderPipeline

Reads **AltTracker SavedVariables** (`AltTracker.lua`) and produces deterministic offline character
portrait renders (`.tga`) plus `AltTrackerRenderManifest.lua` entries for the addon.

Portraits are generated by the **HeroShot** backend using the **codex** provider — it drives the OpenAI
`codex` CLI's built-in `image_gen` tool headlessly (`codex exec`). This uses codex's ChatGPT-login auth,
so **no OpenAI API key is required**. HeroShot is the only render backend.

## Render input data flow

Source of truth is `AltTrackerDB` from SavedVariables. For each character, the pipeline extracts:

- `realm`, `account`, `name`
- `faction`, `race`, `gender`, `class`, `level`
- `lastUpdate` timestamp
- equipped `gear item IDs` by slot (`gearid_*`, with item-link fallback extraction)
- equipped `gear links` by slot (if present)
- computed `gearHash`

## Pipeline stages

1. Load characters from SavedVariables → build render jobs (`RenderPlanner`).
2. For each job: resolve the reference image, build the prompt (`HeroShotPromptBuilder`), call the
   provider (`CodexImagegenProvider`), quality-validate, stage a PNG.
3. Crop + convert the staged PNG to `.tga` (`ImageConverter`, cover-crop to `OutputWidth`×`OutputHeight`).
4. Copy to the addon media dir and write `AltTrackerRenderManifest.lua` (`ManifestLuaStore`).

## Provider: codex imagegen

`CodexImagegenProvider` (`Services/HeroShot/CodexImagegenProvider.cs`):

- Writes the reference image to a temp file and instructs codex to `view_image` it, then generate a **new**
  vertical full-body portrait using it as a visual identity reference.
- Runs `codex exec --ephemeral --skip-git-repo-check --sandbox workspace-write -c model_reasoning_effort=<effort>`,
  feeding the prompt via stdin (closed for EOF) and reading codex's final message from the `-o` file.
- **Fail-closed attribution:** codex saves the image under its own `generated_images` directory; the
  provider snapshots that dir before the run and requires **exactly one** new image afterward (cross-checked
  against the path codex reports). Zero or multiple new files → the job fails rather than risk publishing the
  wrong portrait.
- Validates the harvested file's PNG magic bytes before returning it.

Requires the `codex` CLI installed and ChatGPT-authenticated on the machine (`codex` on `PATH`).

## Config (`appsettings.json`)

```json
"RenderBackend": "HeroShot",
"RenderSpec": {
  "Width": 512,
  "Height": 512,
  "PreferTransparentBackground": true,
  "BackgroundColorFallback": "#141414",
  "FramingPreset": "fullbody_center_v1",
  "PreferredStagingExtension": ".png"
},
"HeroShot": {
  "Enabled": true,
  "Style": "realistic",
  "Width": 1024,
  "Height": 1792,
  "OutputFormat": "png",
  "OutputWidth": 512,
  "OutputHeight": 896,
  "CropMode": "cover",
  "Anchor": "center",
  "Format": "tga",
  "Provider": "codex",
  "Model": "gpt-image-1",
  "PromptTemplateVersion": "v2",
  "GenerationVersion": "1",
  "ReferenceImagesPath": "C:/Projects/AltTracker/Media/References",
  "TimeoutSeconds": 120,
  "MaxRetries": 2,
  "RequireReferenceImage": true,
  "CharacterReferenceImages": {},
  "Codex": {
    "CodexExecutable": "codex",
    "ReasoningEffort": "low",
    "TimeoutSeconds": 360,
    "ExtraArgs": "",
    "EnableWebSearch": false
  }
}
```

- `OutputWidth`/`OutputHeight` (512×896) are the final addon texture dimensions; when `RenderBackend` is
  `HeroShot` these override `RenderSpec`. Final output is always `.tga`.
- `Provider`: `codex` (default) or `manual` (imports the reference image directly, png/jpg/jpeg/tga, no AI).
- `RequireReferenceImage`: when `true`, characters without a resolved reference image are skipped (a
  reference is essential for identity accuracy).
- `Codex.ReasoningEffort`: `low` (default) / `medium` / `high`. `Codex.TimeoutSeconds`: per-generation
  hard timeout (built-in `image_gen` commonly takes 2–4 minutes; no retry happens on timeout).
- `Codex.EnableWebSearch`: `false` (default). When `true`, codex is given its web-search tool and told to
  look up each equipped item by ID (e.g. on Wowhead) before generating, so the transmog matches the real
  in-game model. More accurate for obscure gear, but adds a browsing step per render and consumes OpenAI
  usage. The equipped item names + IDs are placed in the prompt either way; this flag only controls lookup.

### Reference images

Place a reference at `{ReferenceImagesPath}/{outputBaseName}.png` (e.g. `dreamscythe_1_kaleid.png`) or add a
per-character override in `CharacterReferenceImages` (keyed by `Realm:Account:Name`).

### Style presets

| Style | Description |
|---|---|
| `realistic` | Photorealistic fantasy concept art, cinematic lighting (default) |
| `wow-like` | Semi-realistic WoW-style art, vibrant, heroic proportions |
| `cartoonish` | Stylized cartoon, bold outlines, saturated colors |

Override at runtime: `--heroshot-style wow-like`.

### Caching / skip logic

The adapter computes a deterministic SHA-256 signature covering character identity, race/gender/class, gear
item IDs, style, provider, model, and output dimensions. If the signature matches the prior state and both
the staging file and final output exist, generation is skipped. Use `--force-all` to regenerate
unconditionally. State is persisted to `{TempPath}/heroshot/*.heroshot-state.json`.

## Example commands

Plan only (no generation):
```powershell
dotnet run --project .\Tools\AltTracker.RenderPipeline -- --dry-run --verbose
```

Generate one character:
```powershell
dotnet run --project .\Tools\AltTracker.RenderPipeline -- --character "Dreamscythe:1:Kaleid" --verbose
```

Interactive selector (all / selected / stale-only):
```powershell
dotnet run --project .\Tools\AltTracker.RenderPipeline -- --interactive --verbose
```

Publish all pending rerenders:
```powershell
dotnet run --project .\Tools\AltTracker.RenderPipeline -- --verbose
```

Force rerender all:
```powershell
dotnet run --project .\Tools\AltTracker.RenderPipeline -- --force-all --verbose
```

Useful path overrides for a safe test run (write nothing live):
`--output <dir> --addon-media <dir> --manifest <path> --staging <dir> --temp <dir>`.

## In-game validation checklist

1. Run the pipeline and confirm `.tga` output under `Media\CharacterRenders`.
2. Confirm the manifest contains the matching `Realm:Account:Character` key and image path under
   `Interface\AddOns\...`.
3. In WoW, run `/reload`.
4. Verify:
   - current player uses the live model,
   - an offline character with a manifest entry shows the static render,
   - an offline character without an entry shows the offline identity card.
